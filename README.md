# Календарь рабочих задач

Простой календарь задач на чистом HTML/CSS/JS. Месячный вид, клик по дню → панель задач,
drag & drop задач между днями, чекбоксы. Синхронизация телефон ↔ ПК через приватный
GitHub Gist.

## Локальный запуск

Просто открой `index.html` в браузере. Никакой сборки. Без токена всё работает локально
(localStorage в текущем браузере).

## Деплой на GitHub Pages

1. Создай репозиторий на GitHub, например `kalendar`.
2. В этой папке:
   ```
   git init
   git add .
   git commit -m "init kalendar"
   git branch -M main
   git remote add origin git@github.com:<твой-логин>/kalendar.git
   git push -u origin main
   ```
3. На GitHub: **Settings → Pages**.
   - **Source:** `Deploy from a branch`
   - **Branch:** `main` / `(root)` → Save.
4. Через минуту сайт доступен по адресу:
   `https://<твой-логин>.github.io/kalendar/`
5. Обновления — обычным `git push`.

## Синхронизация между телефоном и ПК

GitHub Pages — это только статика, поэтому состояние хранится в **приватном GitHub Gist**.
Каждое устройство держит твой токен у себя в `localStorage` и читает/пишет этот Gist.

### 1. Создай Personal Access Token

GitHub → Settings → **Developer settings** → Personal access tokens → **Tokens (classic)** →
**Generate new token (classic)**.
- Note: `kalendar`
- Expiration: на твой вкус (по истечении токен надо будет обновить в приложении).
- Scopes: отметь **только `gist`**.
- Сгенерируй и скопируй (показывается один раз).

### 2. Открой приложение и впиши токен

1. Нажми ⚙ (правый верхний угол).
2. Вставь токен в поле «GitHub Personal Access Token».
3. Нажми **«Создать новый»** рядом с Gist ID — приложение создаст приватный Gist и
   подставит его ID.
4. Нажми **«Сохранить»**.

### 3. На втором устройстве

1. Открой ту же страницу.
2. Открой ⚙.
3. Вставь **тот же токен** и **тот же Gist ID** (скопируй из первого устройства).
4. Сохрани → данные подтянутся.

### Как это работает

- При любом изменении — debounced PATCH в Gist (≈0.5 сек).
- При возврате на вкладку / выходе онлайн — pull из Gist.
- Если на сервере новее, чем локально — берём серверную версию (мягкое разрешение
  конфликтов; одновременное редактирование с двух устройств может потерять секунды
  правок, но не всю историю).

### Безопасность токена

- Токен лежит **только** в `localStorage` твоего браузера, никуда больше не отправляется
  (только в `api.github.com` с заголовком `Authorization`).
- На общедоступных компьютерах токен не вставляй. Если случайно вставил — кнопка
  «Стереть токен» удаляет его из этого браузера.
- Скоуп токена ограничь `gist` — этого достаточно.
